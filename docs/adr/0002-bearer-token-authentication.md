# ADR-0002: Bearer token at a fixed path; legacy path token deprecated

Status: accepted · Date: 2026-08-19

## Context

The old kit authenticated by placing a 64-hex random token in the URL path
(`/<token>/mcp`). Tokens in URLs leak into shell history, proxy and access
logs, browser history and `Referer` headers. The MCP authorization spec
(2026-07-28) says clients MUST send `Authorization: Bearer <token>` and that
access tokens MUST NOT be in the URI query string; the same reasoning applies
to path segments.

MCPBox is a single-user tool behind loopback/SSH. Full OAuth 2.1 with a
protected-resource-metadata document and an authorization server would add a
lot of moving parts for no security gain in that deployment model, and would
tempt users to expose the port publicly.

## Decision

* Endpoint: `POST /mcp` (configurable `MCPBOX_MCP_PATH`).
* Credential: `Authorization: Bearer <token>`, `token` = contents of
  `runtime/mcpbox-token` (32 random bytes, base64url, generated by
  `setup.sh`). Compared with a constant-time SHA-256 digest comparison.
* Server-side validation of the token file: ≥ 32 chars, allowed charset
  `[A-Za-z0-9._~+/=-]`, ≥ 10 distinct characters; otherwise the server exits
  78 with a message that does not include the token.
* Failures: missing/invalid bearer → `401` with
  `WWW-Authenticate: Bearer realm="mcpbox"` and a generic JSON-RPC error body.
  No OAuth metadata endpoint is served (this is a pre-shared secret, not
  OAuth); clients configured with a static header work with Claude Code and
  Codex.
* Legacy compatibility: when `MCPBOX_LEGACY_PATH_TOKEN=1`, `POST /<token>/mcp`
  is also accepted (bearer header, if present, still wins). Off by default;
  when off the path returns `404` exactly like any unknown path. Every accepted
  legacy request logs a deprecation warning. Scheduled for removal in 2.0.
* The token is never written to logs; log lines carry only status codes and a
  boolean `legacyPath`.

## Consequences

* Users copy the token into their client once (`--header` for Claude Code,
  `bearer_token_env_var` for Codex).
* Anyone with the token has full container access; rotation is a one-liner
  and a container restart.
* This remains a shared secret with no scopes, expiry or per-client identity;
  the security model says so explicitly.
